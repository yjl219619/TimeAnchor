# 阶段 3 / 4 设计备忘（冻结，未实现）

> 状态：**仅记录，不实现**。阶段 1、2 通过后才动。
> 来源：用户 2026-11-27 口述。

## 核心原则
像普通闹钟一样简单。不追问、不延后。

## A 闹钟行为
1. 到点响起，持续响铃，直到用户手动关闭。
2. 关闭按钮文案为 **「开始做：{任务名}」**。点击即停铃，视为已开始该任务，
   这一次提醒彻底结束，不再弹任何通知。
3. **不提供**稍后提醒 / 延后 10 分钟。
   （阶段 1 原型里的「稍后 10 分」按钮仅用于测试；阶段 3 移除，或设置里默认隐藏。）
4. 另提供 **「完成」** 按钮：直接标记任务完成。
5. 已关闭、已完成的任务不得再次提醒。
6. 不自动追着提醒未完成的任务。
7. 同一时刻只显示一个提醒界面，其余排队。

## B 结束提醒（待确认，默认关）
- 每条日程可有结束时间，到点响一次「时间到了：{任务名}」，只说一件事，不询问是否完成。

## C 不做
- 不限制 / 不强制输入文字
- 不做待安排池、不做每日回顾弹窗
- 不做追问

## D 阶段 4：导入日程
- 支持导入 JSON / 文本日程（由用户在 Claude 里生成）
- 预览确认后写入数据库并注册闹钟
- App 本身无网络、无账号

---

## 实现时要先想清楚的三点（留给阶段 3）
1. 状态机需要 `started` 和 `completed` 两个终态：
   「开始做」= started（停铃、不再提醒），「完成」= completed。
   统计只能覆盖用户主动点过的任务，未点的不计入——这与「不追踪」一致，但要在统计页写明口径，避免数据看着像「完成率暴跌」。
2. 移除「稍后」后，阶段 1 的通知动作要跟着改：只剩 开始做 / 完成 两个，
   否则通知和界面的语义会不一致。
3. 结束提醒（B）如果启用，它和 A 的「不追问」有张力：
   结束提醒本质是第二次响，需明确它不算「追问未完成」，而是独立的一次性提醒。
