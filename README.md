# 时间锚点 Time Anchor · 阶段 1

到点必须真正响铃。可靠性优先于功能。

## 已实现（阶段 1 范围）
- `setAlarmClock()` 调度，每条闹钟独立 PendingIntent，requestCode 用**自增计数器**（不是时间戳）
- 响铃：前台服务 + `USAGE_ALARM` + 循环 + 震动 + 音频焦点**只请求一次 EXCLUSIVE**，**失去焦点继续播放**（不暂停、不停止、不轮询）
- 通知兜底：CATEGORY_ALARM，带 停止 / 稍后10分 / 完成 三个动作，全屏界面没弹也能操作
- 全屏界面：`fullScreenIntent` + `showWhenLocked` + `turnScreenOn`
- 多个闹钟同一时刻：进队列排队，先响的继续，后到的接续
- 最长响铃时间：默认 0 = 一直响，可在 Prefs 里设分钟数；超时写入「错过的闹钟」
- 开机 / 应用更新 / 改时间 / 改时区 → 只重建未来闹钟，绝不在广播里启动播放
- 诊断页：通知权限、全屏通知、闹钟音量、勿扰、覆盖勿扰（人工确认）、电池无限制、精确闹钟（参考项）、小米三项（人工确认）、已注册数/错过数、最近日志
- 「测试 30 秒」按钮：走完整链路

## 使用中接管屏幕（三层）
1. `setAlarmClock` + `fullScreenIntent` → 锁屏 / 待机时接管
2. `SYSTEM_ALERT_WINDOW` 悬浮窗（`TYPE_APPLICATION_OVERLAY`）→ 屏幕亮着、正在用别的 App 时整屏覆盖
3. 小米「后台弹出界面」权限 → 不开会被系统拦，诊断页可确认

覆盖层行为：拦截返回键；点空白无效；只有 停止 / 稍后 10 分钟 / 完成 能结束。
**不强制关闭其它 App**，只靠覆盖屏幕 + 独立闹钟音量 + 音频焦点。

## 构建

### Android Studio
1. File → Open → 选 `TimeAnchor` 目录
2. 等 Gradle Sync（第一次会下载 Gradle 8.11.1 + AGP 8.9.1）
3. Build → Build Bundle(s)/APK(s) → Build APK(s)
4. 产物：`app/build/outputs/apk/debug/app-debug.apk`

### 命令行
```bash
cd TimeAnchor
# 需要 JDK 17
echo "sdk.dir=/path/to/Android/Sdk" > local.properties
./gradlew assembleDebug        # Windows: gradlew.bat assembleDebug
```
缺 SDK 组件时：
```bash
sdkmanager "platforms;android-36" "build-tools;36.0.0"
```

## 装好后必做（否则 MIUI 会压掉）
1. 省电策略 → 无限制
2. 自启动 → 允许
3. 权限 → 后台弹出界面、锁屏显示 → 允许
4. 通知 → 声音/振动/悬浮/锁屏 全开
5. 勿扰：关掉，或给通知类别开「覆盖勿扰」
6. 闹钟音量 > 0

## 需真机验证的三处（我不猜）
1. 前台服务类型 `mediaPlayback` 从闹钟广播启动是否被 HyperOS 拒绝 → 日志会记录 `startForeground 失败`
2. `setAlarmClock` 在未授予精确闹钟权限时的准点程度
3. 抖音场景下音频焦点效果（STREAM_ALARM 独立声道是否足够盖过）
